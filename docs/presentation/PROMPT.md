# たびメイト 発表資料 — AIへの指示書

作品紹介（ポートフォリオ）用の PowerPoint を作ってもらうための指示書です。
**このファイルまるごとと、`docs/presentation/img/` `docs/img/` の画像を
AIに渡してください。** これ1つで、そのまま作れるように書いてあります。

- 目的: 作品紹介・ポートフォリオ（就活・作品発表・ポートフォリオサイト添付）
- 想定: 7〜10分・14枚
- 相手: 開発者とは限らない。技術の細かい話より「何を作ったか」が伝わること

---

## 0. 何よりも先に — このアプリの世界観

たびメイトは **絵本みたいにやさしい、旅の相棒アプリ** です。
マスコットの **ちゃむ**（四つ葉を持った白いうさぎ）が旅に寄り添う、という
世界観でできています。**資料もその声のままで作ってください。**

守ること:

- **やさしい話しことばで書く。** 「〜を実現しました」ではなく「〜できます」。
  体言止めの羅列や、硬い提案書の言い回しにしない
- **ひらがなを多めに。** 「旅のまえ」「ふりかえり」「おすそわけ」など、
  アプリの中で使っている言い方をそのまま使う
- **ちゃむを主語にしてよい。** 「ちゃむが選んでくれます」は正しい書き方
- 絵文字は 🍀 を軸に、控えめに。装飾で埋めない

やらないこと:

- 「革新的」「圧倒的」「業界初」のような、盛った言葉
- 数字の水増し。**この資料に書いていい数字は §5 の事実シートだけ**
- 技術用語をただ並べること（LangGraph も「10人のエージェント」と説明してから名前を出す）

## 3. 1枚の作り方（共通）

各スライドは **見出し1つ＋メッセージ1つ**。箇条書きは多くて3つまで。

```
┌────────────────────────────────┐
│  小見出し（濃い緑・小さく・字間広め）        │  ← 任意
│  見出し（大きく・太く）                    │
│                                            │
│  ［画像か、2〜3個のカード］                 │
│                                            │
│  添える一文（#8A817A）                     │  ← 任意
└────────────────────────────────┘
```

**話す原稿は必ずノート欄（スピーカーノート）に入れてください。**
スライドの上には置かない。原稿は §4 に各スライドぶん書いてあります。

## 4. スライド 1枚ずつ

> 「画面に出す文」は**そのまま**使ってよい文です。
> 「ノート」は発表者が読む原稿。だいたい 1枚 30〜45秒。

### 1. 表紙

- 画像 `01-cover.png` を**全面に**。文字は重ねない（画像に入っている）
- ノート:
  「たびメイト、と読みます。旅のしおりをAIが作って、帰ってきたら
  写真がひとりでに付箋になる、絵本みたいなアプリです。
  この子はマスコットのちゃむ。今日はこの子と一緒に案内します。」

### 2. ひとことで言うと

- 見出し: **旅の「まえ」と「あと」だけを、ぜんぶ引き受けるアプリ**
- 画面に出す文（大きめに3行）:
  - 話すだけで、しおりができる
  - 写真を入れるだけで、思い出が残る
  - どちらも、ちゃむがやっておく
- ノート:
  「旅行アプリはたくさんありますが、たいてい『予約』のためのものです。
  たびメイトが引き受けるのは、その前後。計画を立てるところと、
  帰ってきてから振り返るところ。ここが一番めんどうで、
  一番たのしいところだと思ったからです。」

### 3. なぜ作ったか

- 小見出し: `WHY`
- 見出し: **計画はめんどう。ふりかえりは、しないまま終わる**
- カード3つ:
  - 🗺️ **調べるのが大変** — 行き先を決めても、店・宿・順番で手が止まる
  - 📷 **写真は撮るだけ** — カメラロールに埋もれて、見返さない
  - 📝 **記録は続かない** — 旅行記を書くのは、思ったより重い
- 添える一文: どれも「やる気」の問題ではなく、**手間**の問題だと考えました
- ノート:
  「自分が旅行するときに困ったことが、そのまま出発点です。
  計画は情報が多すぎて手が止まるし、帰ってきたら写真は撮ったきり。
  やる気がないんじゃなくて、単に手間が多いだけだと思ったので、
  その手間をAIに預けられないか、というのがこのアプリです。」

### 4. 体験の流れ

- 画像 `02-journey.png`（横いっぱい）
- ノート:
  「使う流れはこの4つです。話す、しおりができる、旅に出る、ふりかえる。
  それぞれ次のページから実際の画面でお見せします。
  最後の『おすそわけ』は、リンクひとつで人に見せられる機能です。」

### 5. 旅のまえ ①　話すだけで、しおりができる

- 左: `screen-plan-detail.png`（高さいっぱい）
- 右: 説明3つ
  - 💬 行き先・日数・予算をふつうの会話から読み取り、**足りないことだけ**聞き返す
  - 🌤️ 旅の日の予報を見て、雨なら屋内多め。閉まっていそうな店は外す
  - 🍽️ 候補は Google Places で突き合わせ、**架空の店を落とす**
- ノート:
  「『金沢に2泊3日で』と話しかけると、足りない情報だけ聞き返してきて、
  あとは勝手に組み立ててくれます。
  こだわったのは2つ。ひとつは天気を見ること。雨の日に屋外だらけの
  予定を出されても困るので。もうひとつは、実在の店だけ残すこと。
  AIはそれらしい店名を作ってしまうので、Google Places で照合して
  見つからない名前は落としています。」

### 6. 旅のまえ ②　できたしおりは、本棚に並ぶ

- 左: `screen-bookshelf.png`（**上 780×1400 で切って使う**）
- 右: 説明3つ
  - 🗾 観光・食事・宿を色分けしたピンを、**まわる順**につなぐ水彩の地図
  - 🎒 行き先と天気から持ち物リスト。チェックすると四つ葉が咲く
  - 🍀 「あと12日」— 棚を開けるたびに出発が近づく
- 添える一文: `.ics` で書き出せば、いつものカレンダーにも入ります
- ノート:
  「作ったしおりは本棚に並びます。ここが開くのが楽しくなるように、
  出発までのカウントダウンを出しています。
  地図は水彩のタイルを使っていて、ピンをまわる順につないであります。
  『どこにあるか』より『どういう順で歩くか』が知りたいので。」

### 7. 旅のあと　写真が、ひとりでに言葉になる

- 左: `screen-journal.png`（高さいっぱい）
- 右: 説明3つ

  大事にしたのは、写真の説明にしないこと。『海が写っています』では

### 12. こだわったところ

- 見出し: **見た目も、中身も、こわれないように**
- カード3つ:
  - 🎨 **世界観をずらさない** — 色・角丸・言い回しをアプリ全体でそろえた。
    ちゃむの言葉づかいはプロンプトにも書いてある
  - 🧵 **生成を捨てない** — 途中でリロードされても、AIの返事は保存される。
    画面を開き直せば続きから見える
  - 🧪 **こわれたら気づける** — テストは **APIキーなしで139件**通る。
    画面まわりは本物のブラウザで触って確かめる検査を別に持たせた
- ノート:
  「3つあります。ひとつは世界観。色も言葉づかいも1か所にまとめて、
  ページごとにバラバラにならないようにしました。
  2つめは、生成を捨てないこと。最初は画面を閉じるとプランが消えていて、
  原因を追ったら、保存する処理が画面に送る側にぶら下がっていました。
  作る側に移して直しました。
  3つめはテストです。AIも外部APIも差し替えてあるので、
  キーがなくても全部通ります。」

## 5. 事実シート（**この数字以外を書かないこと**）

すべて 2026-09-07 時点のリポジトリで実測した値です。

| 数字 | 意味 | 測り方 |
|---|---|---|
| **10** | プラン生成のエージェント | `src/chat/agents.py` のノード関数。うち8つが LangGraph のグラフ内、2つ（`transport` / `sightseeing_candidates`）はグラフの外で並列先行 |
| **67** | HTTPルート | `app.url_map`（`static` を除く）。うち `/api/*` が6 |
| **139** | 自動テスト | `pytest tests/ -k "not smoke"`。APIキー不要でオフラインで通る |
| **11** | ブラウザ検査 | `scripts/check_home_js.sh`。ヘッドレス Chromium で画面を実際に触る |
| **2** | プラットフォーム | Web（PWA）と iOS。同じサーバー・同じアカウント |
| 7,589行 | `src/**/*.py` | 参考値。弱い指標なので、聞かれたときだけ答える |
| 6,340行 | `ios/**/*.swift` | 同上 |

## 7. 図を作り直したいとき

図は手で描いたものではなく、`build_images.py` が HTML を
ヘッドレス Chromium で撮って作っています。数字や構成が変わったら
このファイルを直して、

```bash
python3 docs/presentation/build_images.py
```

で7枚ぜんぶ作り直せます（Chromium の場所は `CHROME_PATH` で変えられます）。
**作り直す前に §5 の数字を測り直してください。**
